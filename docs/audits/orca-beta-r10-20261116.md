# ORCA beta R10: webpage fragment tolerance and desktop server rollout

Date: 2026-11-16. Internal candidate, not a release certificate.

## The blocked failure, identified

R9's real task died on `raw_fragment_type_unknown` at the second answer. The
cause is not an unknown page format; it is our own parser being narrower than
the site.

The public site bundle (`main.9eec11d937.js`, already retained under
`.tmp/integration-20261115-r2/public-deepseek-assets/`) defines:

    RESPONSE_TYPES: ["RESPONSE","TEMPLATE_RESPONSE"]
    MAIN_RESPONSE_TYPES: ["RESPONSE"]
    FILE_TYPES: ["FILE"]
    TOOL_TYPES: ["TOOL_SEARCH","TOOL_OPEN","TOOL_FIND"]
    SEARCH_TYPES: ["SEARCH","TOOL_SEARCH"]
    TIP_TYPES: ["TIP"]
    THINK_TYPE: "THINK"
    READ_LINK_TYPE: "READ_LINK"

`raw-response.js` accepted only `THINK` and `RESPONSE` and failed the whole turn
on anything else. The site emits the other categories routinely, so a normal
answer that carried one was discarded. The site also lists `TEMPLATE_RESPONSE`
as answer-bearing; we treated it as an error.

A second, quieter mismatch: `response/status` accepted only
`WIP/FINISHED/THINKING/RUNNING`, while the site's status enum is
`OK(=FINISHED)/WIP/INCOMPLETE/CONTENT_FILTER/CONTEXT_LENGTH_EXCEEDED/TIMEOUT`.
A truncated, filtered, over-length or timed-out answer therefore reported
"unknown status", which pointed at the wrong cause.

## Source changes

- Answer-bearing types are `RESPONSE` and `TEMPLATE_RESPONSE`. When both exist,
  `RESPONSE` wins, so a template placeholder switching to the real answer does
  not trip the rewrite guard.
- Every other site type is inert: content is not published, never becomes
  executable text, and the turn continues. The fixed label
  (`raw_fragment_type_<category>`) is still recorded for diagnosis.
- Terminal statuses map to `raw_status_incomplete`,
  `raw_status_content_filter`, `raw_status_context_length` and
  `raw_status_timeout`; `raw_status_unknown` remains for genuinely unknown
  values. These four are added to the Go diagnostic allowlist.
- `captureWebTaskDrain` now bounds the drain wait at 30 seconds instead of
  waiting on `context.Background()`. An uncooperative native stream previously
  held the parent turn open, silently dropping every later Submit.

Two attempts were reverted after repository tests refuted them, and both
failures are recorded rather than hidden:

- Resetting `webBetaAdmission.blocked` on a failed account switch or logout.
  `web_beta_switch_windows_test.go` requires the gate to stay closed after a
  failure; retry goes through `webBetaUseCurrentLogin`, which does not consult
  that gate, and only a confirmed switch reopens it.
- Adding a grace timer to the `releaseTaskScope` fallback goroutine. It hung the
  close-time wait group (`lifecycle.go:211`). The bounded wait belongs at the
  caller, which is where it now lives.

## Account entry: one capsule, both connections

The header carried an icon-only account button (`UserRound`, 28x26) that named
neither connection and did not say whether either was signed in, plus two copies
of the same entry in submenus. The user asked for one prominent control showing
both states, and for the duplicates to go.

- Removed the duplicate `ModernMenuItem` in the settings submenu
  (`AppChrome.tsx`) and the duplicate button in the topic overflow menu
  (`App.tsx`). `Settings -> account` remains reachable through the capsule only,
  which is the entry that states whether anything needs attention.
- `BetaConnectionsEntry` is now a blue capsule (`--beta-pill-*` tokens in
  `beta-connections.css`) with two segments: the ORCA account (`UserRound`) and
  the DeepSeek Web connection (`Globe`). Signed out shows `登录` / `Log in`;
  signed in shows the account name. The Web segment shows connected, retained,
  not connected, or attention. Segment text collapses to icon plus tooltip
  below 1500px so narrow windows keep both states legible.
- Signed in switches the capsule to a tinted blue outline so a signed-out call
  to action stays the loudest state on the bar; any error turns it amber.
- `readBetaAccountSummary` (`lib/betaBridge.ts`) polls every 5 seconds and on
  window focus while the panel is closed, so an authorization completed in the
  external browser appears without opening the panel. `readOrcaAccountStatus`
  coalesces concurrent reads: the panel's 1.5s poll and the capsule share one
  in-flight request instead of stacking two against the same endpoints.

Verification: `beta-connections.browser.cjs` 16 cases / 546 assertions pass,
`beta-recovery` 108 pass, `beta-account-switch` 68 pass, `classic-layout` 574
assertions with zero failures, `ui-style-contract` and `beta-connections`
unit suites pass. `modern-polish` reports 6 failures in composer
cancel/pause runtime state; that suite has no beta bindings at all
(`BetaCapabilities` absent), so the capsule never renders there and the
failures predate this change.

One defect was introduced and fixed during this work: rewriting the capsule CSS
dropped `.beta-entry-slot { position: relative }`, so in the Classic frame the
entry positioned against the window and the maximize button intercepted its
click at 1920px. The browser suite caught it via the real-click step.
